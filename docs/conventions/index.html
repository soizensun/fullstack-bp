Project Conventions — Index

The single entry point to this project's conventions. Humans read it to know what exists; AI agents read it to decide which document to open before touching code. Every entry maps to one document in docs/conventions/<AREA>/. Click any entry below to open its document; entries still marked todo have no file yet and do not open.

How this index works

  1. Every convention lives in exactly one document, filed under its area: docs/conventions/GEN/, INFRA/, BE/ or FE/. An entry's data-file is the bare file name; the folder is its data-area.
  2. The id encodes area + read order — BE_01 is read before BE_02. The tier says who has to read it; the number says in what order.
  3. Nothing in a document may contradict a lower-numbered document of the same area. If it must, change the lower-numbered one and record an ADR (GEN_13).
  4. A document's requires may never be a lower tier than the document itself. If it is, one of the two tiers is wrong. This page checks it on load.
  5. If the code and a document disagree, the document wins — unless the document is older than the code it describes and unreviewed, in which case stop and ask.

Out of scope for this doc set, on purpose: product process, multi-tenancy, email/notification templates, and anything specific to one product built on this document set. Do not go looking for a document that was never meant to exist — write an ADR in the project that needs it instead.

Contract for AI agents working in this repository

  • Read set. Read every P0 before any change. Read <AREA>_01 through the last P1 of an area once, when you start working in that area. Then read any P2 whose Open when trigger matches the change in front of you.
  • data-paths on an entry lists the globs it governs. If your change touches a matching file, that document is in your read set regardless of tier.
  • Cite the convention ids you relied on, in your plan and in the PR description.
  • While a document's status is todo, its index entry is the only binding text: follow the summary, do not infer beyond it, and say in your plan which todo entries you had to interpret. When two entries conflict, stop and ask.
  • Never weaken a guardrail (lint rule, architecture test, type check, CI gate) to make a change pass.
  • Follow GEN_04 for features and GEN_05 for bugs. No code before the workflow's first step is done.

Hard rules — these five need no document

  • No secret, token, or credential in source, in a commit, or in a URL.
  • No personal data in logs, traces, analytics payloads, or error messages.
  • No .env committed. .env.example is the only one in git.
  • No design value hardcoded in the frontend — tokens only (FE_03).
  • No cross-module database join or transaction in the backend (BE_03).

Priority tiers

  • P0 · 10 documents Binds every change, in any area. Adding one means demoting one.
  • P1 The entry path for one area. Read once, when you start working there.
  • P2 Read when its Open when trigger matches your change.
  • P3 Read when the project scales, splits, or breaks.

Status vocabulary

  • todo Not written. The index entry is the binding text.
  • draft Written, not agreed. Follow it, but challenge it in review.
  • stable Agreed. Changing it needs an ADR.
  • deprecated Superseded. The entry says by what.

  • GEN_05

  • GEN_10

    P1

    Open when: you are writing acceptance criteria or a .feature file.

  • GEN_11

    [General] Data primitives — ids, dates, money & units

    P1

    Open when: you are modelling an id, a timestamp, an amount of money, or a quantity.

    UUIDv7 for public ids, UTC everywhere with the timezone applied at the edge, money as integer minor units, and the ban on floating-point currency and locale-dependent parsing.

  • GEN_12

    [General] How to write a convention document

    P1

    Open when: you are writing or updating a document in this folder.

    The required shape of every document here — Rule, Rationale, Do / Don't with real code, Enforcement, Related — so a human can skim it and an agent can extract the rule without reading the prose. Includes how to add an entry to this index.

  • GEN_13
